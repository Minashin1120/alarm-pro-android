# サブエージェント運用

MathWake では、コストの中心が「調査・読解」と「実装」にあるため、**調査とレビューだけ**をサブエージェントに分離します。実装・commit・push・CI 確認は親エージェントが担当します。

## エージェント

| エージェント | 用途 | モデル | 権限 |
|---|---|---|---|
| `recon` | 関連ファイル、既存パターン、制約、リスク、必要テストの調査 | `deepseek-flash#low` | 読み取り専用。edit と shell を拒否（読み取り系 git のみ許可） |
| `reviewer` | 差分レビュー、AGENTS.md の不変条件チェック | `deepseek-flash#low` | 読み取り専用。edit を拒否（`git diff` 等のみ許可） |

どちらも `steps` を制限し、サブエージェントの起動も禁止しています。

## 標準フロー

1. 親が `AGENTS.md` と依頼内容を確認する
2. `recon` に調査を依頼する
   - 例: 「`recon` サブエージェントで、QRスキャン解除の実装箇所と制約を調査して」
3. 親が設計・実装する
4. `reviewer` に差分レビューを依頼する
   - 例: 「`reviewer` サブエージェントで現在の差分をレビューして」
5. 親が commit / push / CI 確認を行う
6. CI 失敗時は、ログをファイルに保存して `recon` に原因分析だけを依頼する

## CI ログの渡し方

`recon` は shell で CI ログを取得できないため、親が取得してファイルに保存します。

```bash
gh run view <run-id> --log > /tmp/mathwake-ci.log
```

その後、`recon` に `/tmp/mathwake-ci.log` の解析を依頼します。ログ全文を親の会話に貼らずに済みます。

## 分割しない工程

- 設計と実装（密結合なため、親が一貫して担当）
- commit / push / CI 待ち
- AGENTS.md の更新（最後に親が 1 回で行う）
- 小さな単一ファイル修正

## 注意

- サブエージェントは親の会話を引き継がないため、依頼時に目的・対象・制約を明示する
- `AGENTS.md` の制約を子が破らないよう、`recon` には必ず `AGENTS.md` を読ませる
- サブエージェントの結果を鵜呑みにせず、親が最終判断する
